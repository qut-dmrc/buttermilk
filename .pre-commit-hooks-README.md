# Pre-commit Hooks for Buttermilk

This repository uses [pre-commit](https://pre-commit.com/) to enforce code quality, security, and repository standards.

## Installation

Pre-commit hooks are automatically installed when you run:

```bash
uv run pre-commit install
```

This installs both `pre-commit` and `commit-msg` hooks.

## What Gets Checked

### Security (CRITICAL - ZERO TOLERANCE)

- **Detect secrets**: Scans for API keys, tokens, passwords, and other credentials
- **API key patterns**: Additional checks for common API key formats
- **Large file detection**: Prevents accidentally committing large files (>1MB)

### Code Quality

- **Ruff linter**: Fast Python linting (replaces flake8, pylint)
- **Ruff formatter**: Code formatting (replaces black)
- **mypy**: Type checking for Python code

### File Formatting

- **yamlfmt**: YAML formatting (consistent indentation, structure)
- **mdformat**: Markdown formatting with GitHub Flavored Markdown support
- **JSON5 checking**: Validates JSON files, including VSCode configs with comments
- **check-jsonschema**: Validates JSON schemas, GitHub Actions workflows, and Dependabot config
- **End-of-file fixer**: Ensures files end with newline
- **Trailing whitespace**: Removes trailing whitespace

### Repository Rules (Based on [docs/agents/INSTRUCTIONS.md](docs/agents/INSTRUCTIONS.md))

#### 🔴 CRITICAL: Security Violations

Pre-commit will **BLOCK** commits containing:

- Real API keys, tokens, or secrets
- Long alphanumeric strings matching key patterns (`sk_`, `pk_`, `tl_`, etc.)

**Fix**: Use environment variables or secret managers instead.

#### ❌ Standalone Validation Files

Pre-commit will **BLOCK** commits containing:

- Test files outside `tests/` directory
- Validation scripts: `test_*.py`, `verify_*.py`, `check_*.py`, `validate_*.py`
- Demo/example scripts: `demo_*.py`, `example_*.py`

**Fix**: Put all tests in `tests/` directory using pytest conventions.

#### ❌ Repository Issue Tracking Files

Pre-commit will **BLOCK** commits containing:

- `*_README.md`, `*_NOTES.md`, `*_STATUS.md`
- Progress tracking or bug-specific documentation files

**Fix**: Use GitHub issues for tracking bugs, features, and progress.

## Running Manually

### Run all hooks on all files

```bash
uv run pre-commit run --all-files
```

### Run specific hook

```bash
uv run pre-commit run detect-secrets --all-files
uv run pre-commit run ruff --all-files
```

### Run hooks on specific files

```bash
uv run pre-commit run --files path/to/file.py
```

### Partial commits (staged files only)

Pre-commit hooks run **only on staged files** by default. You can safely:

```bash
# Stage only specific files
git add file1.py file2.py

# Commit only staged files - hooks run only on these files
git commit -m "Partial commit"

# Other modified files remain untouched
```

This is the default behavior - no special configuration needed.

### Skip hooks (EMERGENCY ONLY - use with caution)

```bash
git commit --no-verify -m "Emergency commit"
```

**WARNING**: Only use `--no-verify` in genuine emergencies. All skipped checks should be addressed in follow-up commits.

## Managing Secrets Baseline

The `.secrets.baseline` file contains known false positives for secret detection.

### Update baseline after reviewing findings

```bash
uv run python -m detect_secrets scan --baseline .secrets.baseline
```

### Audit existing baseline

```bash
uv run python -m detect_secrets audit .secrets.baseline
```

## Hook Configuration

Hooks run in this order:

1. **Security checks** (detect-secrets, large files)
1. **Syntax checks** (JSON, YAML, merge conflicts)
1. **Formatters** (yamlfmt, mdformat, ruff-format)
1. **Linters** (ruff, mypy)
1. **Repository rules** (standalone validation prevention, issue tracking prevention)

## Troubleshooting

### JSON syntax errors in VSCode config files

VSCode config files (`.vscode/*.json`) use JSON5 format with comments. The `check-json5` hook validates these properly.

### Hook fails with "command not found"

Ensure pre-commit environments are installed:

```bash
uv run pre-commit install-hooks
```

### Update hooks to latest versions

```bash
uv run pre-commit autoupdate
```

### Clear hook cache

```bash
uv run pre-commit clean
uv run pre-commit install-hooks
```

## Integration with CI/CD

Pre-commit hooks should also run in CI/CD pipelines to catch issues before merge:

```yaml
# Example GitHub Actions workflow
- name: Run pre-commit
  run: |
    uv run pre-commit install-hooks
    uv run pre-commit run --all-files
```

## Philosophy

These hooks enforce the [FAIL FAST](docs/agents/INSTRUCTIONS.md#L154) principle documented in our agent instructions:

1. **Security**: Zero tolerance for credential exposure
1. **Repository cleanliness**: Use proper tools (GitHub issues) instead of tracking files
1. **Test conventions**: All tests in `tests/` directory with pytest
1. **Code quality**: Consistent formatting and linting
1. **Observability**: Mandatory type hints and documentation
